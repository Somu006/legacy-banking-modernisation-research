Problem statement-

India's banks and public-sector institutions run core operations on COBOL systems written decades ago, maintained long after their original authors retired. The barrier to modernising them is widely misunderstood: it is not translation. Transpilers and code-generation tools already produce valid modern equivalents. Migrations stall because the business logic was never documented anywhere except in the code — accrual conventions, rounding behaviour, and hundreds of edge cases patched in over decades. No specification exists, so no team can prove a rewritten system behaves identically to the one it replaces. For a bank, a one-paisa discrepancy across millions of accounts is a regulatory event, so the organisation rationally keeps running software it cannot safely change. The bottleneck is verification, not code generation.

Explain the solution in brief

We treat legacy modernisation as a verification problem rather than a translation problem. The system ingests legacy source, decomposes it into functional units, and states each unit's business rules in plain language, with every rule traced to the lines that produce it. Because a confidently stated wrong rule is more dangerous than no rule, extraction alone is not the deliverable. The system then generates inputs targeting the boundaries those rules imply, executes both the original program and a generated modern reimplementation against every input, and compares the outputs. The legacy program serves as the correctness oracle — it already defines the right answer by running, so nobody has to specify expected behaviour in advance. Every mismatch surfaces as a reproducible case: given this input, the old system returns X and the new one returns Y. Rules confirmed by execution are marked verified; rules never exercised are marked unproven rather than silently trusted. The output is a specification the organisation never had, a permanent regression test suite, and an evidence-backed equivalence claim. We scope to COBOL interest-accrual programs executed via GnuCOBOL; whole-system migration is out of scope.
