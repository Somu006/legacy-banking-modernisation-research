## The two papers that matter most

### Locksmith — the closest prior art

**Ferenczi, A., Docherty, J., Bessonov, M., Findlay, M., Lingamneni, K.**
*Agentic Method for Deterministic Validation of Legacy Code Migration.*
arXiv:2607.28271 [cs.SE], 30 July 2026. 11 pages, 6 figures.
PDF: https://arxiv.org/pdf/2607.28271 · Abstract: https://arxiv.org/abs/2607.28271

**Used for:** `../03 §1`, `../07 §B`, `Solution Folder/04`.

The same architecture as this project: legacy COBOL as execution oracle via a
*Parity Gate*, both targets run **off-mainframe on commodity hardware** with
mocked external calls, inputs generated by *Witness Search*, parity-preserving
mutations to reach new paths, *Locked Paragraphs* identified as exploration
blockers. Three case studies, 430–4,114 LOC, **91.90% branch coverage** on a
production-like program, full parity on all accepted tests.

**Why it matters to you:** it cost the "no mainframe needed" claim its absolute
form, and it is the single strongest piece of evidence that your architecture
works. Verified to contain **no business-rule verdicts and no regulatory
checks** — that absence is what your novelty now rests on. Read this one
properly before the next round.

### AgentModernize — falsified one of our novelty claims

**Ahmed, S. N., Galib, M.** *AgentModernize: Preserving Business Logic in Legacy
Modernization with Multi-Agent LLMs and Behavioral Specification Graphs.*
arXiv:2605.17535 [cs.SE], 17 May 2026. 11 pages, 9 tables, 2 figures.
PDF: https://arxiv.org/pdf/2605.17535 · Abstract: https://arxiv.org/abs/2605.17535

**Used for:** `../02 §7`, `../03 §3a`, `../07 §C3`.

Defines **Business Rule Preservation Score** (gold-standard rules counted as
preserved when they appear in the behavioural specification *and* the modernised
code enforces them, verified by targeted tests) and **Behavioural Equivalence
Rate**.

**The number to quote:** the behavioural specification graph captured **91.2% of
gold-standard rules**, while BER reached only **9.4% (GPT-4o-mini), 8.1%
(GPT-4o), 19.4% (codex)** — baselines **0.0%**. Extraction works; behavioural
equivalence does not follow from it. That pair is the sharpest argument in the
whole dossier for verification over extraction.

## LLM translation reliability

**Pan, R., Ibrahimzada, A. R., Krishna, R., Sankar, D., Wassi, L. P., Merler, M.,
Sobolev, B., Pavuluri, R., Sinha, S., Jabbarvand, R.** *Lost in Translation: A
Study of Bugs Introduced by Large Language Models while Translating Code.*
ICSE 2024. arXiv:2308.03109, 6 August 2023.
PDF: https://arxiv.org/pdf/2308.03109

**Used for:** `../01 §5`, `../02 §2`. Correct translations **2.1%–47.3%** across
studied LLMs; 1,700 code samples; 1,748 manually labelled bugs in **15
categories**; 43K+ translations; 1,365 bug-fix pairs; prompt crafting improved
performance by 5.5% on average.

**Beyond Translation Accuracy: Addressing False Failures in LLM-Based Code
Translation.** arXiv:2605.02195, 2026. ⚠ **Author list not verified.**
https://arxiv.org/abs/2605.02195

**Used for:** `../02 §2`. Silent failures from operator-semantics differences —
the canonical case being modulo on negative operands, where Python takes the
divisor's sign and Java/C take the dividend's.

## COBOL translation validation

**Hans, S., Kumar, A., Yasue, T., Ono, K., Krishnan, S., Sondhi, D., Satoh, F.,
Mitchell, G., Kumar, S., Saha, D.** *Automated Testing of COBOL to Java
Transformation.* arXiv:2504.10548, 14 April 2025. DOI 10.48550/arXiv.2504.10548
PDF: https://arxiv.org/pdf/2504.10548

**Used for:** the headline quote in `../01 §5` and throughout. IBM's testing
framework for watsonx Code Assistant for Z. Symbolic execution generates unit
tests from COBOL with external calls mocked, converted to JUnit to validate
semantic equivalence. **This is the source of the "cannot be trusted" line —
see `05 - Verified quotes.md` for the exact wording.**

**Kumar, A., Saha, D., Yasue, T., Ono, K., Krishnan, S., Hans, S., Satoh, F.,
Mitchell, G., Kumar, S.** *Automated Validation of COBOL to Java Transformation.*
ASE 2024. arXiv:2506.10999. ⚠ **Submission date reported inconsistently with the
arXiv identifier — verify before citing.**
https://arxiv.org/abs/2506.10999

Companion paper to the above; surfaced during the verification pass and **not
read in full**.

**Froimovich, S., Gal, R., Ibraheem, W., Ziv, A.** *Quality Evaluation of COBOL
to Java Code Transformation.* Submitted to ASE 2025. arXiv:2507.23356,
31 July 2025. PDF: https://arxiv.org/pdf/2507.23356

**Used for:** `../03 §1`. IBM Research. Analytic checkers combined with
LLM-as-a-judge for scalable translation-quality evaluation in CI.

**Entin, P., Gu, W., Knapp, A., Chen, C.** *SEDCoT: Enhancing LLM-Based COBOL
Code Translation via Symbolic Execution and Delta Debugging.* arXiv:2607.04092,
5 July 2026. PDF: https://arxiv.org/pdf/2607.04092

**Used for:** `../02 §2`, `../02 §5d`. COBOL as a low-resource language for LLMs.
Three phases — initial translation, symbolic-execution-guided repair, delta
debugging to minimise counterexamples. At least **12%** over SOTA baselines.
**Delta debugging (phase three) is the technique behind N10.**

## Business rule extraction

**Shah, S., Agarwal, S., Krishnan, S., Kanvar, V., Chimalakonda, S.**
*A-COBREX: A Tool for Identifying Business Rules in COBOL Programs.*
ICSE 2025, Demonstrations Track. IIT Tirupati / IBM Research India.
https://research.ibm.com/publications/a-cobrex-a-tool-for-identifying-business-rules-in-cobol-programs

**Used for:** `../02 §4`, and the central "extraction is ~a quarter wrong"
argument. **Recall 74.12%, precision 62.21%** for fuzzy match against ground
truth on 27 annotated programs.

**B S, C., Chimalakonda, S.** *LLM Vs Rule-Based — The COBRAIN Tool and An
Empirical Study on Extracting Business Rules from COBOL.* EASE 2025.
DOI 10.1145/3756681.3756982 · https://dl.acm.org/doi/10.1145/3756681.3756982

**Used for:** `../02 §4`. **Precision 1.0, recall 0.746** vs COBREX;
**F1 0.73 vs COBREX's 0.59** against ground truth. Over 80% of 28 participants
found COBRAIN's output more understandable. Evidence that LLM extraction beats
rule-based extraction — which justifies using a model for stage 3.

⚠ **Paywalled (ACM DL).** Check OUTR institutional access.

**COBREX: A Tool for Extracting Business Rules from COBOL.** ⚠ **Authors not
verified.** https://www.semanticscholar.org/paper/543a21dba8546db505057b0c4b4f096b9e981f24
Rule-based CFG slicing; F1 ≈ 0.59. The baseline COBRAIN is measured against.

**Cosentino, V., et al.** *Extracting Business Rules from COBOL: A Model-Based
Framework.* ⚠ **Only the first author is verified;** the HAL page blocked
automated access. https://inria.hal.science/hal-00869235/document
Foundational pre-LLM work: model the COBOL, identify business-concept variables,
slice. **The origin of the slicing approach behind N6.**

## Orchestration

**Lwin, N. O., Kumar, R.** *Deterministic vs. LLM-Controlled Orchestration for
COBOL-to-Python Modernization.* arXiv:2605.09894, 11 May 2026.
PDF: https://arxiv.org/pdf/2605.09894

**Used for:** `../02 §2`, `Solution Folder/03`. Controlled study holding models,
prompts, tools and source constant while varying only the control strategy.
Deterministic execution reduces token consumption by **up to 3.5×** at
comparable accuracy, with better worst-case robustness and lower run-to-run
variance. **The justification for a fixed pipeline over an agentic one.**

## Hallucination in code understanding

**Hallucinations in LLM-Based Code Summarization: Unveiling, Detection, and
Mitigation.** Proceedings of the ACM on Software Engineering, 2026.
DOI 10.1145/3808139 ⚠ **Authors not verified.**

**Used for:** `../02 §2` — the measured basis for "a confidently stated wrong
rule is more dangerous than no rule." Hallucination rates up to **66%**, reduced
to 59% by mitigation; Hallu-Det detection F1 0.95.

**Beyond Functional Correctness: Exploring Hallucinations in LLM-Generated
Code.** arXiv:2404.00971. ⚠ **Authors not verified.**
Taxonomy of 3 primary and 12 specific hallucination categories.

**Boundary Value Test Input Generation Using Prompt Engineering with LLMs.**
arXiv:2501.14465. ⚠ **Authors not verified.**
**Used for:** `../02 §5a` — LLM-driven boundary value generation.

**Business as Rulesual: A Benchmark and Framework for Business Rule Flow
Modeling with LLMs.** arXiv:2505.18542. ⚠ **Authors not verified.**
BREX benchmark; 13 SOTA LLMs; expert annotation with ICC/Kappa agreement.
